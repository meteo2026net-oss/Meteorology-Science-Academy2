# أكاديمية علوم الأرصاد الجوية

منصة تعليمية عربية لإعداد وتأليف ونشر دروس علوم الأرصاد الجوية، مع مسارات تأسيسية في الرياضيات والفيزياء، واختبارات ومختبرات ومحاكاة تعليمية.

## صفحات المنصة

- `index.html` — الصفحة الرئيسية والمكتبة التعليمية.
- `lesson.html` — عارض الدروس المنشورة مع تسجيل إكمال الدرس في حساب الطالب.
- `account.html` — بوابة تسجيل الدخول وسجل الاختبارات والتقدم الدراسي.
- `exams.html` — مركز الاختبارات والتصحيح المركزي وسجل المحاولات والشهادات.
- `exam-studio.html` — استوديو المدير لإدارة بنك الأسئلة وإنشاء ونشر نماذج الاختبارات.
- `lesson-quiz-studio.html` — ربط الاختبارات القصيرة بالدروس وإدارة المدة ودرجة النجاح والنشر.
- `verify-certificate.html` — صفحة عامة للتحقق من رمز الشهادة دون كشف بيانات الحساب.
- `labs.html` — المختبرات العلمية والمحاكاة التعليمية.
- `editor.html` — استوديو تأليف الدروس وكتل المحتوى.
- `preview.html` — معاينة محلية للمسودة قبل نشرها.
- `hierarchy.html` — إدارة الفصول والوحدات وربط الدروس.
- `admin.html` — إدارة المقررات والدروس.
- `content-review.html` — مراجعة المسودات ومعاينتها ونشر مجموعة مختارة بعد التأكيد.
- `students.html` — إحصاءات الطلاب والإنجازات ونتائج الاختبارات؛ للمدير فقط.
- `diagnostics.html` — فحص اتصال قاعدة البيانات والجداول والمخزن؛ للمدير فقط.

## البنية التقنية

- واجهة ويب عربية RTL باستخدام HTML وCSS وJavaScript Modules.
- Supabase Auth لإدارة حسابات الطلاب والمديرين.
- PostgreSQL لتخزين المقررات والدروس والفصول والوحدات والتقدم ومحاولات الاختبار.
- Supabase Storage للملفات التعليمية.
- Row Level Security (RLS) لحماية بيانات الطلاب وحصر إدارة المحتوى بالمدير.
- مكتبة Supabase JS مثبتة على إصدار CDN محدد في الصفحات.

## إعداد Supabase

1. تأكد من أن مشروع Supabase نشط.
2. راجع ونفّذ `supabase/schema.sql`.
3. نفّذ `supabase/content_cms.sql` لإضافة حقول إدارة المحتوى.
4. نفّذ `supabase/hierarchy.sql` لإنشاء هيكل الفصول والوحدات.
5. نفّذ `supabase/storage.sql` لإنشاء مخزن الملفات وسياسات الوصول.
6. نفّذ `supabase/exam_certification.sql` لإنشاء بنك الأسئلة الخاص ومحرك التصحيح المركزي والشهادات.
7. نفّذ `supabase/exam_security_hardening.sql` لتأمين واجهات التصحيح والتحقق من الشهادات.
8. نفّذ `supabase/exam_studio.sql` لإضافة أدوات تأليف الأسئلة ونماذج الاختبارات.
9. نفّذ `supabase/exam_delivery.sql` لإتاحة الاختبارات المنشورة وجلسات التوقيت والتصحيح المرتبطة بنموذج الاختبار.
10. نفّذ `supabase/exam_question_enrichment.sql` لتوسيع خصائص بنك الأسئلة وإضافة المجموعة التطبيقية الأولى.
11. نفّذ `supabase/exam_attempt_blueprint_link.sql` لربط المحاولات بنماذج الاختبارات والمقررات.
12. نفّذ `supabase/exam_session_cancel.sql` لتمكين الطالب من إنهاء جلسة غير مكتملة دون تسجيل محاولة.
13. نفّذ `supabase/lesson_quizzes.sql` لإضافة الاختبارات القصيرة المرتبطة بالدروس.
14. نفّذ `supabase/lesson_quiz_course_state.sql` لتضمين حالة نشر المقرر في بيانات استوديو اختبارات الدروس.
15. نفّذ `supabase/lesson_quiz_validation_hardening.sql` لمنع نشر اختبار درس قبل نشر المقرر والدرس، والتحقق الصارم من إجابات التسليم.
16. نفّذ `supabase/progress_policy_performance.sql` لتوحيد سياسات تقدم الطالب وفهرسة مفاتيح الربط.
17. نفّذ `supabase/meteorology_question_batch_2.sql` لإضافة 16 سؤالاً تطبيقياً إضافياً في الأرصاد.
18. نفّذ `supabase/visual_meteorology_question_batch.sql` لإضافة أسئلة تحليل خرائط وقراءة بيانات مع رسوم SVG أصلية.
19. نفّذ `supabase/meteorology_interpretation_batch_3.sql` لإضافة أسئلة تحليل المسبار الرأسي ومرور الجبهات والهطول.
20. نفّذ `supabase/seed_draft_lesson_quizzes.sql` لإنشاء ستة اختبارات أولية كمسودات مرتبطة بدروس الأرصاد المناسبة.
21. ضع رابط المشروع ومفتاح Publishable في `supabase-config.js`. لا تضع مفتاح `service_role` أو أي مفتاح سري في ملفات المتصفح.
22. أنشئ حساب المسؤول من `account.html`، وأكمل تأكيد البريد إذا كان مفعلاً.
23. بعد إنشاء الحساب، استبدل البريد في `supabase/bootstrap_admin.sql` بالبريد الفعلي، ثم نفّذ الملف يدوياً من SQL Editor بصلاحية موثوقة.
24. سجّل الدخول من `admin.html` أو `editor.html` لبدء إدارة المحتوى، وافتح `exam-studio.html` لإدارة بنك الأسئلة ونشر الاختبارات، أو `lesson-quiz-studio.html` لربط الاختبارات القصيرة بالدروس.

لا تمنح حساباً دور المدير عبر واجهة عامة. ترقية الدور عملية إدارية موثوقة فقط.

## سير نشر المحتوى

1. أنشئ الدرس أو حرّره من استوديو التأليف.
2. استخدم المعاينة المحلية لمراجعة المحتوى.
3. افتح `content-review.html` لمراجعة المسودات.
4. حدد الدروس التي اكتملت مراجعتها العلمية والتحريرية فقط، ثم انشرها.
5. تأكد من نشر المقرر نفسه من لوحة الإدارة؛ نشر الدروس وحدها لا يجعلها مرئية إذا بقي المقرر مسودة.

## حفظ التقدم والاختبارات

- لإتاحة اختبار درس: انشر المقرر أولاً، ثم الدرس بعد مراجعته، ثم افتح `lesson-quiz-studio.html` واختر الدرس والأسئلة واحفظ الاختبار منشوراً. لا تظهر الاختبارات للطلاب إذا بقي المقرر أو الدرس مسودة.

- يتطلب حفظ التقدم تسجيل دخول الطالب.
- زر «إكمال الدرس» يحفظ حالة الإكمال في `academy_lesson_progress`.
- اختبارات الدروس تظهر فقط عندما يكون الدرس والمقرر منشورين ويكون المدير قد نشر الاختبار المرتبط به.
- يختار المدير الأسئلة والمدة ودرجة النجاح من `lesson-quiz-studio.html`؛ لا تُرسل الإجابات الصحيحة إلى واجهة الطالب أثناء الاختبار.
- يبدأ الاختبار بجلسة خادمية محددة المدة، ويجري التصحيح في PostgreSQL، ثم تُحفظ النتيجة في سجل المحاولات وتُحدّث نتيجة تقدم الدرس. النجاح يعلّم الدرس مكتملاً تلقائياً.
- اختبارات الدروس تظهر فقط عندما يكون الدرس والمقرر منشورين ويكون المدير قد نشر الاختبار المرتبط به.
- يختار المدير الأسئلة والمدة ودرجة النجاح من `lesson-quiz-studio.html`؛ لا تُرسل الإجابات الصحيحة إلى واجهة الطالب أثناء الاختبار.
- يبدأ الاختبار بجلسة خادمية محددة المدة، ويجري التصحيح في PostgreSQL، ثم تُحفظ النتيجة في سجل المحاولات وتُحدّث نتيجة تقدم الدرس. النجاح يعلّم الدرس مكتملاً تلقائياً.
- الاختبارات المركزية تتطلب تسجيل الدخول؛ تُجلب الأسئلة من `get_academy_exam_questions` دون مفاتيح الإجابة.
- نماذج المدير المنشورة تظهر في `exams.html` عبر `get_published_academy_exams`.
- `supabase/exam_question_enrichment.sql` يضيف تصنيف نوع السؤال وهدف التعلم والصيغة والوسائط والوسوم، ويضيف 12 سؤالاً تطبيقياً جديداً في سياق الأرصاد.
- `supabase/exam_attempt_blueprint_link.sql` يربط محاولة الطالب بنموذج الاختبار والمقرر ويحفظ بيانات السؤال الإثرائية في سجل المراجعة.
- بدء اختبار منشور ينشئ جلسة خادمية محددة المدة، ويحفظ قائمة الأسئلة وتاريخ الانتهاء على الخادم.
- `submit_defined_academy_exam` يتحقق من ملكية الجلسة والأسئلة ووقت التسليم، ثم يصحح وفق درجة النجاح الخاصة بنموذج الاختبار.
- يُرسل الطالب اختياراته فقط إلى `submit_academy_exam`، ويجري PostgreSQL التصحيح وحساب النتيجة وحفظ المحاولة.
- لا يملك المتصفح صلاحية إدخال أو تعديل محاولات الاختبار مباشرة، ولا يستطيع قراءة بنك الإجابات الخاص.
- تُصدر شهادة داخلية تلقائياً عند اجتياز نموذج منشور وفق درجة النجاح التي حددها المدير، وترتبط بمحاولة محفوظة. أما التدريب الحر القديم فيستخدم حد الاجتياز 70%.
- تعرض بوابة الطالب الشهادات، وتعرض لوحة المدير عدد الشهادات لكل الأكاديمية ولكل طالب.
- يستطيع الطالب قراءة تقدمه ونتائجه فقط، بينما تعرض لوحة `students.html` البيانات الإجمالية للمدير بعد التحقق من الدور وسياسات RLS.
- الشهادات تعليمية داخلية ولا تمثل اعتماداً أكاديمياً أو مهنياً رسمياً.
- تبقى بعض أدوات التعلم الذاتي المحلية قابلة للاستخدام دون حساب، لكن الاختبارات المركزية والشهادات لا تعمل دون جلسة مستخدم.

## تحليلات إتقان الأهداف التعليمية

- أضيفت الدالة `get_academy_objective_mastery` لتحليل إجابات المحاولات المصححة خادمياً حسب هدف التعلم، مع استخدام الموضوع بديلاً عندما يكون حقل الهدف فارغاً.
- يستطيع المدير طلب تحليل طالب محدد، بينما لا يستطيع الطالب طلب بيانات مستخدم آخر؛ الوصول يمر عبر دالة خاصة تتحقق من `auth.uid()` ودور المدير.
- تعرض لوحة `students.html` عدد الإجابات والمحاولات والدقة وآخر نشاط لكل هدف.
- يتيح `lesson-quiz-studio.html` تصفية بنك الأسئلة بحسب نوع السؤال وهدف التعلم/الموضوع، لتسهيل بناء اختبار متوازن مرتبط بمخرجات الدرس.
- لا يصدر تصنيف إتقان قبل خمس إجابات موزعة على محاولتين على الأقل؛ وتبقى العينة الأقل موسومة بأنها غير كافية.
- لا نحسب صعوبة السؤال أو معامل التمييز إحصائياً قبل توافر حجم عينة مناسب.

نفّذ `supabase/objective_level_learning_analytics.sql` بعد migrations السابقة.

## دفعة الدروس التطبيقية الأولى (100 درس)

1. الأرصاد التشغيلية للطيران والمطارات.

3. الأرصاد الزراعية وإدارة العمليات الحقلية.

6. الأرصاد وجودة الهواء وانتقال الملوثات.

كل درس يتضمن نواتج تعلم، شرحاً علمياً وتشغيلياً، بيانات ومدخلات، منهجية تحليل، حالة تدريبية افتراضية، مهمة عملية، أخطاء شائعة وخلاصة. جميع الدروس والفصل والوحدات الجديدة محفوظة كمسودات غير منشورة وتحتاج إلى مراجعة علمية وتحريرية قبل النشر.

ملف الدفعة: `supabase/applied_sectoral_meteorology_lessons_batch_01.sql`
ملف استكمال أمثلة الدروس بحلول تفسيرية: `supabase/applied_sectoral_lesson_example_solutions.sql`.

## سير مراجعة المحتوى والحوكمة قبل النشر

أضيف سير مراجعة علمية وتحريرية موثق لكل درس:

- `private.academy_lesson_reviews` لتسجيل قرار المراجعة وملاحظات المراجع وهوية المراجع وتوقيتها.
- `set_academy_lesson_review` لحفظ قرار الاعتماد أو طلب التعديل أو الرفض؛ متاح للمدير المسجل فقط ويتطلب ملاحظات لا تقل عن 20 حرفاً.
- `get_academy_lesson_review_status` و`get_academy_lesson_review_summary` لعرض حالة المراجعة في لوحة الإدارة.
- `private.academy_lesson_review_events` سجل تدقيق إضافي للقرارات السابقة، مع واجهة لعرض سجل كل درس.
- حارس قاعدة البيانات يمنع نشر درس غير معتمد، أو قبل نشر المقرر والفصل والوحدة الأب. كما يعيد المحتوى المعدل إلى حالة انتظار المراجعة، ويمنع تعديل محتوى درس منشور قبل إلغاء نشره.

الواجهة: `content-review.html`.

ملفات SQL:
- `supabase/lesson_scientific_review_workflow.sql`
- `supabase/lesson_review_trigger_policy_fix.sql`
- `supabase/lesson_review_audit_and_summary.sql`
- `supabase/index_lesson_review_reviewer_fk.sql`

- `supabase/guard_course_chapter_unit_publication.sql` و`supabase/fix_hierarchy_publish_trigger_insert_guard.sql`: حماية تسلسل نشر المقرر ثم الفصل ثم الوحدة ثم الدرس.
- `supabase/index_lesson_review_reviewer_fk.sql`: فهرسة مفتاح المراجع الأجنبي.
- `students.html`: تصدير تقرير الطلاب المحمّل بصيغة CSV من لوحة الإدارة، إلى جانب تقارير التقدم والإتقان.

اختبارات تحقق قاعدة البيانات المنفذة داخل كتل اختبار معزولة: منع نشر درس دون اعتماد، ومنع نشر فصل قبل المقرر، ومنع نشر وحدة قبل الفصل. انتهت الاختبارات الثلاثة بنجاح ولم تُغيّر بيانات المحتوى.

## تقارير إتقان الطلاب

أضيف `get_academy_lesson_objective_mastery` لقراءة تقدم الطالب بحسب أهداف الدروس ودرجاته المسجلة، مع السماح للطالب بقراءة بياناته فقط وللمدير بقراءة طالب محدد. يتطلب التصنيف ثلاث نتائج دروس مقيمة على الأقل، ولا يصدر حكماً من بيانات قليلة.

تم توسيع `students.html` لعرض تحليل إجابات بنك الأسئلة وتحليل أهداف الدروس معاً.

ملف SQL: `supabase/admin_lesson_objective_reporting.sql`.

جميع الوظائف الجديدة تستخدم أقل صلاحيات ممكنة، ولا تمنح `anon` صلاحية تنفيذ تقارير الطلاب أو قرارات المراجعة. لا يوجد نشر تلقائي ضمن هذه التغييرات.

أضيفت دفعة ثانية من 100 درس مسودة، موزعة على عشر وحدات: النمذجة العددية، الأقمار الصناعية، رادار الطقس، الديناميكا والطبقات العليا، Skew-T والمسبار الرأسي، التحقق الاحتمالي، الآنكاستنغ، التنبؤ التجميعي، إدارة التنبؤ، والذكاء الاصطناعي للأرصاد.

جميع الدروس الجديدة والفصول والوحدات مسودات غير منشورة. لا تستنتج إحصاءات صعوبة أو تمييز سيكومتري قبل توفر حجم محاولات كافٍ.

## التشغيل والنشر

يمكن تشغيل المشروع محلياً عبر خادم ثابت مثل VS Code Live Server أو عبر GitHub Codespaces. لا تعتمد على فتح ملفات HTML مباشرة عند استخدام ES Modules أو مكتبات CDN.

للنشر الثابت يمكن استخدام Netlify أو GitHub Pages. تأكد من ضبط مجلد النشر على جذر المستودع، ومن أن إعدادات Supabase وRedirect URLs تسمح بنطاق الموقع المنشور.

## تنبيهات

- محتوى المحاكاة التعليمية لا يُستخدم بديلاً عن أدوات الرصد أو التنبؤ التشغيلي.
